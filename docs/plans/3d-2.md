# 3D slice 2: persistent scene and camera

Slice 2 of the 3D lane (touche `docs/decisions/2026-11-09-3d-surface-first.md`;
the lane's brief is `docs/briefs/GPU_SURFACE_3D_BRIEF.md`, slice 2 under
"Implementation slices"). Acceptance, as reconciled with Tom on 2026-11-09:
show a mesh through Group/Mesh and both camera projections; prove parent
transforms, active-camera validation, invalid-input refusal and lifecycle
cleanup; compare ground and object projection so their transforms cannot
diverge unnoticed.

It also closes the two gaps IU0 found for the 3D slices
(`docs/design/incremental-contracts.md` section d): no check counts scene draw
calls, and nothing says how a scene node's signal change reaches the surface's
invalidation.

Slice 1 is done (`docs/gpu-surface.md`): the scene renderer is a
`SurfaceRenderer` on a `gpu-surface`. The racer keeps its own renderer; slice 2
does not port it.

Each PR is under about 400 lines and is built by a fresh agent. Each check is
proven by breaking what it guards, watching it fail and restoring it.

## The ground and object check

A ground plane (a mesh, y = 0) carries a marker at world point P, and an object
mesh stands at P. Rendered through one camera, the marker's centre and the
object's base land on the same backing pixel, and that pixel is
`Projection::project(P)` mapped to the viewport, within one pixel, for both
projections and for a camera moved after mount. The ground and the objects go
through one view-projection matrix, so the check fails if either path takes its
own (as the racer's ground shader and solid pipeline each build theirs today).

## Decisions

Asked 2026-11-10; answered the same day.

1. **How scene nodes appear in `.wisp`** (Tom): Rust components with typed
   props, `<Scene>`, `<Group transform={..}>`, `<Mesh geometry={..}
   material={..}>`, `<Camera>`, mounted through the existing component-tag
   path. Each keeps one inert anchor element for identity and lifecycle
   (`{for}` and `{if}` anchors, the children snippet's parent); no compiler
   or document change. The docs say the anchor is `display: none` and outside
   the accessibility tree. Not chosen: lowercase elements in the document;
   a Rust API only in slice 2.
2. **The active camera** (lead): the scene root names it by handle
   (`camera={handle}`); a handle no camera holds, or held by two cameras, is
   refused, naming the fix. Not chosen: a per-camera `active` flag.
3. **Matrix maths** (lead): `glam`, pinned to an exact version, with
   `cargo xtask deny` passing; a needed `deny.toml` change stops the work
   for Tom's clear. Not chosen: our own `Vec3`, `Quat`, `Mat4`.
4. **Scene draws in `FrameCounts`** (lead): `SurfaceFrame` lets the renderer
   report its `GpuWork`, and `FrameCounts::surfaces` adds it to the
   composition draws, closing IU0's draw-call gap for scenes. Not chosen:
   counts kept by the scene renderer alone.
