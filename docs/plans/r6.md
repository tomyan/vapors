# R6: the web page mirrors the a11y tree into the browser

Status: design, 2026-11-12. Slice A3 of `docs/design/05-accessibility.md`
("A DOM mirror on the web"), moved ahead of touche's web MVP by Tom on
2026-11-12: touche's top bar, tool cards and launcher are drawn on the
canvas and no screen reader or browser automation reaches them. touche's
row for it: `docs/plans/driving.md` R6.

What exists (R1a, R1b: PRs #135 to #137): `Document::ax_tree()`
(`crates/elements/src/a11y_tree.rs`) builds the whole tree from the last
update on every call: roles (`a11y_roles.rs`), names (`a11y_name.rs`),
values, descriptions and states, pinned against Chromium by the corpus's
`ax_oracle`; `ax_find`, `ax_press`, `ax_focus`, `ax_type`, `ax_key` and
`ax_set_value` act on a node by role and name through the pointer and
key paths. The local branches `a11y-act`, `a11y-command`, `a11y-drive`
and `a11y-set-value` in `~/projects/vapors` are the pre-squash sources
of those PRs; main is ahead of each in every a11y file, so nothing is
reused from them. The web platform owns one DOM element already: the
hidden textarea of `crates/platform/src/text_bridge_web.rs`, set from
the app in `App::drawn` through `Platform::set_text_field` and applied
by the handler (`handler.rs` `redraw_if_asked`). The frame has an
`accessibility` phase (`crates/app/src/frame.rs`) that does nothing yet,
and `vapors-perf --scaling` judges every `frame phase` span.

## What a reader gets

A hidden DOM subtree beside the canvas, one element per node of
`ax_tree()`, nested as the tree nests, with the node's role, name,
value, description, states and bounds, and DOM focus following vapors'
focus. A screen reader (TalkBack, VoiceOver, NVDA through the browser)
reads the mirror; its activation, focus and keys come back to vapors
through the same paths a pointer and keyboard use, so a handler cannot
tell a reader from a person. Browser automation (`Accessibility.*` over
CDP, Claude in Chrome's tree) sees the same.

## Element mapping

Every mirror element is a `<div>`; the role is always explicit.

| Node | Mirror |
|---|---|
| role | `role="<role>"`, the ARIA token vapors' tree holds (`img`, not Chromium's `image`) |
| name | `aria-label="<name>"`; no attribute when empty |
| description | `aria-description` when present; exposed by Chromium and by NVDA/JAWS/TalkBack through it, partially by Firefox and Safari, which is the gap readers of those have |
| value, `slider` and `spinbutton` | `aria-valuenow`, `aria-valuemin`, `aria-valuemax` from the element's range (`range.rs`: `min`, `max`, HTML's defaults 0 and 100) |
| value, `textbox` and `combobox` | the element's text content, which is how Chromium computes a non-native textbox's value; checked by the oracle below |
| `disabled` | `aria-disabled="true"` when set |
| `checked`, `expanded`, `pressed` | `aria-checked`, `aria-expanded`, `aria-pressed` with `true` or `false` when vapors has the state; no attribute when it has none |
| `selected` | `aria-selected="true"` when set; `aria-selected="false"` on an `option` without it (required there) |
| `focused` | DOM focus (below), never an attribute |
| focusable (`focus_candidate`) | `tabindex="-1"`: `.focus()` works, and the browser's own Tab order does not compete with vapors' |
| bounds | `style="position:fixed;left:<x>px;top:<y>px;width:<w>px;height:<h>px"`: viewport coordinates, the record's CSS pixels plus the canvas's client rect origin (0,0 when the canvas fills the viewport, as the demos and touche have it). `position: fixed` on every element makes the viewport its containing block whatever it nests in, so a child's offsets are not added to its parent's; the nesting carries the tree's structure only. A reader's highlight and a touch exploration's hit-test land on the pixels |
| identity | `data-node="<NodeId number>"`, the key every update and every action uses |

The root: `<div id="vapors-a11y">` appended to `<body>` by the platform
when the page opens, `position: fixed; inset: 0; overflow: hidden;
pointer-events: none; opacity: 0`, so presses reach the canvas and
nothing is painted; its own place does not matter to the elements'
bounds, which are fixed too. `opacity: 0` keeps an element in the
accessibility tree of every engine (`visibility: hidden` and
`display: none` take it out); Chromium is checked by the oracle below,
WebKit/VoiceOver on iOS is not checked by anything here and is named
as unverified in touche's R6 row until an iPhone runs it. The canvas
gets `aria-hidden="true"`: it has no content of its own. The hidden
textarea is covered by "The focused text field" below.

### Refused, not approximated

A node is refused, naming its role and name, when ARIA requires a state
vapors' tree does not carry, since the browser would read a default that
may be wrong (a `slider` with no value is read as 0 of 100): `heading`
(needs `aria-level`), `meter` (needs `aria-valuenow`), `scrollbar`
(needs `aria-controls` and `aria-valuenow`), `combobox` (needs
`aria-controls`), a `checkbox`, `radio`, `switch`, `menuitemcheckbox` or
`menuitemradio` without `aria-checked` (a native `<input
type=checkbox>` has it), a `slider` without a value, a `separator` that
takes focus without `aria-valuenow`, and an `aria-checked` or
`aria-pressed` of `mixed`, which the tree reads as none (`AxStates`
holds `true`/`false`; `mixed` is A6). `AxError::Unexposable { role,
name, needs }` names what is missing and the slice that adds it; the
frame stops in the `accessibility` phase (`FrameError` names the
phase), as a refused document stops it in `update`. The checks are
`unexposable` in `a11y_mirror_roles.rs`; a role not in ARIA 1.2 cannot
reach the mirror (`a11y_roles.rs` takes only those). touche uses
`status`, `log`, `img`, `toolbar`, `region`, `alert`, buttons and
inputs, none refused.

Focus on an element the tree leaves out (a `tabindex="0"` element with
no role) is refused too, `AxError::FocusOutsideTree { tag }`: the
mirror would have nothing to focus and a reader would hear nothing, so
the fix is a role and a name on the element, or focus kept on a node.

Not refused, named: a role whose ARIA context is missing (`option`
outside a `listbox`, `tab` outside a `tablist`, `menuitem` outside a
`menu`, `row` or `cell` outside a table). Chromium exposes it with the
role given; some readers drop it. Checking context needs the parent's
role at every take of the child, which is A6's element references.

## Update strategy: only what changed

`Document::take_ax_update()` returns what changed since the last take,
as one `AxUpdate`:

```
AxUpdate {
    every: bool,                 // `nodes` holds every node: the first take, or every box built
    removed: Vec<NodeId>,        // nodes no longer in the tree
    nodes: Vec<AxMirrorNode>,    // nodes new or whose record changed (role, name, value, description, states, range, focusable, bounds)
    placed: Vec<AxPlace>,        // nodes new or moved: { node, parent: Option<NodeId>, before: Option<NodeId> }
    focus: Option<Option<NodeId>>, // the focused node, when it changed; None = no node has focus
}
```

Cost is proportional to the nodes touched since the last take, never to
the page. The touched set is collected where changes happen, not found
by a walk:

- the update's `ChangedSlots` (rebuilt, freed and moved slots), mapped
  to their elements through `Slots::key`. Every setter marks the box
  of the element it changes (`dom_impl.rs`, `checkbox.rs`,
  `range_input.rs`, `text_field.rs`, `number_text.rs`), and a restyle
  that changes a style builds the box again, so the boxes built again
  are the elements changed, each one, including every element under an
  attribute such as `aria-hidden` or a class; a box that moved because
  of an edit elsewhere (a scroll, an insert above it) is touched for
  its bounds; every box that went (`display: none`, a removed subtree)
  is touched, which is how removals are found without a walk. The
  tests pass with no other source (checked by removing the setter
  hooks a first draft had);
- `insert_before` records the child in `ax.replaced` as well as
  touching it: it may have moved among its siblings with its box built
  the same;
- focus: `focused` compared with the last take's;
- an inserted element that is not a node reaches the nearest nodes under
  it: moved with it while their boxes may be built the same (absolutely
  positioned, the shape of popovers, toasts and tool cards), so no box
  names them. Cost: the inserted element's subtree down to its nodes.

For each touched element: its nearest a11y ancestor is found by walking
up (`O(depth)`), and the element's text changes reach the nodes named by
content above it and the nodes whose `aria-labelledby` or
`aria-describedby` names an ancestor's id (a reverse index of those
attributes, rebuilt only when a touched node carries an `id` or one of
the two attributes, or the tree's shape changed). Each affected node's
record is computed as `ax_tree()` computes it today (the same functions)
and compared with the last emitted record, kept in a `NodeMap`; only a
difference is emitted. A node that no longer qualifies (no box, not
visible, `aria-hidden`, no role, detached) is `removed`; one that lost
its role but kept its box re-parents its a11y children to its a11y
parent, which is a placement for each. `AxPlace::before` is the next
a11y sibling in document order that is in the tree after the take
(kept, or placed in this update), found by scanning forward from the
node's position, `O(siblings)` of the edit; `placed` is ordered so that
a placement comes after the one placing its `before`, so a mirror
applies them one by one with `insertBefore` (or `appendChild` when
`None`). A mirror applies an update as records, then placements, then
removals, then focus: a child re-parented out of a node removed is
moved before the node goes. The tests' `support::mirror::Model` is
that consumer, and proves each placement by the order it leaves.

The index of ids (`a11y_mirror_index.rs`: each id's first element, the
elements naming each id, and what each element put in) is kept between
takes and patched for the touched nodes: each one's entries are dropped
and read again, O(touched). It is rebuilt by a scan of the document only
when the tree's shape changed (an element inserted or removed: its
hidden descendants carry ids without boxes, so no touch names them) or
an id is carried by more than one element (document order says which
wins, and only a scan knows it). Either way the ids whose element
changed are reported, and the nodes naming them (`aria-labelledby`,
`aria-describedby`, the old referrers and the new) are read again, so a
name follows its target when the target goes or changes its id.
`Document::ax_take_counts()` (`AxTakeCounts`: nodes read, index
entries read, index scans, placements considered) counts a take's work
as `UpdateCounts` counts an update's, and `a11y_mirror_scaling.rs`
holds the counts at 100 and 400 rows: a focus move and a state change
read the same nodes on both and scan nothing; a scroll reads the rows
it moved and scans nothing; an insert and a removal scan once each; a
role removed over K children orders its K placements in steps that
grow with K, at most three per placement.

A refused take (`Unexposable`, `NotFinite`, `FocusOutsideTree`) is its
own state, not "nothing changed": what it touched, the nodes it found
renamed and the index it read are kept for the next take, which emits
every change the refused one held once its cause is gone. Placements
are ordered in one pass (each indexed by the placement it waits on,
each placed releasing its dependants); a set that waits on itself,
which document order cannot produce, is `AxError::PlacementCycle`
naming the nodes, never a panic (a panic in wasm kills the page).

`every` on a mirror that already holds elements is a reconcile keyed by
`data-node`, never a rebuild: each record's element is reused and
updated, moved to its parent in order, or created; elements for nodes
not in `nodes` are removed. Recreating elements would drop DOM focus
and the reader's virtual-cursor position, and `changed.every` fires on
viewport changes, which on a phone include rotation and the soft
keyboard.

Known non-constant costs, stated here: an insert or remove costs the
scan for `before` and, through layout's `moved`, the boxes it shifted,
which is the cost the finish line accepts for property 3 today
(`docs/plans/perf-finish-line.md`); a scroll touches every box that
moved in the scroller (bounds change), `O(rows in the scroller)`, the
same remainder IU4 bounds on the paint side.

### Where it runs and how it is measured

`ElementsApp`'s `accessibility` phase (`frame.rs`) takes the update when
a consumer is attached (`ElementsApp::mirror_a11y(true)`; the web
platform asks for it, native does not until R7), inside the
`frame phase` span `accessibility`, and hands it to the platform in
`drawn` (`Platform::set_ax_update`), as the text field is. `Phases::
accessibility` returns a `Result` so a refusal stops the frame, named.
The Rows workload of `vapors-perf` turns the mirror on, so
`vapors-perf --scaling Text|Class|HoveredClass|Idle` judges the phase
with the others: it fails, naming `accessibility`, when the phase grows
by more than 2% and 5000 instructions from 1000 to 3000 or 10,000 rows.
The PR records the counts at 1000 and 3000 rows in `docs/perf/`.

## Focus protocol: one state, projected

vapors' `focused` is the one focus state. The mirror follows it:

- `AxUpdate::focus = Some(Some(node))`: the handler calls `.focus()` on
  the node's mirror element, with `preventScroll`, unless the text
  bridge mirrors a field (the hidden textarea must keep DOM focus for
  the IME; the textbox's own mirror element is a later slice, below).
- `Some(None)`: focus goes to the canvas, as the text bridge does when
  its field goes (a blur would leave it on `<body>`, where winit hears
  no keys).
- `focusin` on a mirror element whose node is not vapors' focused node
  (a reader moved focus) sends `Event::AxFocus { node }`; the app
  scrolls the node into view (`scroll_into_view`, as `ax_press` does;
  `Document::focus` does not scroll) and calls
  `Document::focus(Some(node))`, which fires `blur`/`focus` as a Tab
  would. Nothing happens when the node has focus already, so the
  projection's own `.focus()` does not echo. A node inside a vapors
  scroller is reached this way; a reader driving the scroller itself
  (TalkBack's scroll gestures, scroll actions on a scrollable element)
  finds no scrollable element in the mirror: slice A7 of
  `05-accessibility.md`, reader-driven scrolling.
- Keys while a mirror element has DOM focus: `keydown`/`keyup` listeners
  on the root forward them as `Event::Key`, as the textarea's listeners
  do (`text_bridge_web_view.rs` `key`), with the default prevented for
  every key but a Control or Meta chord, so Tab moves vapors' focus, not
  the browser's. Each key carries the event target's `data-node`:
  accessibility focus is not DOM focus on mobile and in NVDA/JAWS browse
  mode, so a reader's increment on a slider arrives on the element under
  the reader's cursor; when that is not vapors' focused node, the app
  focuses it first (`AxFocus`, above), then delivers the key, so the
  key reaches the node the reader meant.

### The focused text field

While the text bridge holds a field (`Platform::set_text_field`), the
hidden textarea is the element a reader meets: it drops
`aria-hidden`, and takes the field's `role` (`textbox`, or
`searchbox`), `aria-label` and `aria-description` from the node's
record, so a reader Tabbing into touche's prompt hears its name and
role, and its echo and cursor reading come from the textarea's text,
which the bridge keeps in step for the IME. The field's own mirror
element is `aria-hidden="true"` meanwhile, so the field is met once,
and `.focus()` is not called on it (the textarea must keep DOM focus).
When the field goes, the textarea takes `aria-hidden` back and the
mirror element is shown again. This is the focused-field piece of A4,
brought into the focus-and-actions PR; the rest of A4 (static text,
inline text boxes, selection) stays out.

## Action routing: through the person's paths

- `click` on a mirror element (what a reader's activate dispatches)
  sends `Event::AxPress { node }`; the app presses the node as
  `ax_press` does for a driver: scrolled into view, the pointer moved to
  its centre, down and up there (`Document::ax_press_node`). A node that
  is disabled or covered is refused as `ax_press` refuses it, reported
  through the app's error path, never swallowed.
- A reader's increment and decrement on a slider arrive from Chromium as
  arrow keys on the element under the reader's cursor, which the key
  forwarding covers (target carried, above); whether TalkBack
  synthesises them for an ARIA slider is checked on the Pixel in the
  focus-and-actions PR, and named in touche's R6 row if it does not.
- An activation arrives once, by one of two paths that exclude each
  other: a `click` dispatched on the element itself (TalkBack, NVDA,
  JAWS and VoiceOver on macOS act on the node: Chromium fires `click`
  on it with no pointer events, and `pointer-events: none` keeps it out
  of hit-testing, so no pointer path reaches it) becomes `AxPress`; a
  synthesised tap at the element's centre (VoiceOver on iOS) is
  hit-tested, misses the mirror and reaches the canvas as a real press
  at those pixels, which the bounds place on the node. Neither path
  produces the other's event, so nothing is deduplicated; the Pixel
  check in the focus-and-actions PR asserts one count change per
  TalkBack double-tap on the counter.
- Value changes on a textbox come through the text bridge, unchanged.

Every `Event::Ax*` carries the mirror's `data-node`; one that names a
node no longer in the tree is refused, naming it, since the mirror
lagged the document by a frame.

## Testing

Unit (`crates/elements/tests/a11y_mirror*.rs`, the unit tier): every
test applies each take to a model mirror (`support::mirror_model::
Model`: records, each parent's children in order, focus; records, then
placements in order, then removals, then focus, as the web mirror
applies them) and holds the model against
`Document::ax_mirror_snapshot()`, every node as a first take would hold
it now, after every take, so a take that lost a change fails whatever
else the test looks at. Then: the first take holds every node and
`every`; a text change under a button emits that button's record alone;
a class toggle that changes nothing a11y emits nothing; `aria-expanded`
set emits one record; an insert emits one record and one placement
whose `before` is the next kept sibling; a removal emits `removed`; a
node hidden by `display: none` removes its subtree; a role removed
re-parents its children; focus moving emits `focus` and the two
records; a refused role is `Unexposable`, named; a refused take keeps
its changes for the next; a removed or re-id'd `aria-labelledby` target
renames its referrer; a moved absolute wrapper places the nodes it
holds; focus on an element with no role is refused; the index scans
are counted; a node touched then unchanged emits nothing.

Headless Chromium (`scripts/web-a11y-mirror.sh`, the gpu job after the
web build, as `web-text-input.sh` runs): the built page's `checkbox`,
`slider` and `counter` demos opened at 640x400 with WebGPU on
SwiftShader; `Accessibility.getFullAXTree` reduced by the corpus's
`ax_tree::reduce` to the nodes under `#vapors-a11y`; compared with the
same demo's document updated natively at the same viewport and
projected by `ax_projection` (roles, names, values, descriptions,
states, as the a11y oracle compares them), and bounds: `DOM.getBoxModel`
of each `data-node` element against its record's bounds, which pins
the nested offsets (a nested element's box must equal its record, not
its record plus its parent's). Then focus: a Tab through
CDP's `Input.dispatchKeyEvent`, and `document.activeElement.dataset.
node` must be the node vapors focused (its record is in the mirror's
`data-focused`); a click dispatched on a mirror button must run the
demo's handler (the counter's count changes). Every wait has a deadline
from `web_input.rs`'s numbers.

## Out of scope, named

- Text: static text, paragraphs and inline text boxes are not in
  `ax_tree()` (slice A4); a reader meets controls, not prose. The
  focused text field is the one piece of A4 in R6 (above).
- Live regions (A5): a `status`, `log`, `alert`, `timer` or `marquee`
  element is live in every browser without being asked (implicit
  `aria-live` and `aria-atomic`), so the mirror sets
  `aria-live="off"` on those roles' elements: a `status` node's text
  change is a record change, and no reader announces it, until A5 adds
  live regions on purpose (text content as the name, coalescing). With
  the default left on, what a reader announced would depend on the
  reader (names are `aria-label`, which NVDA and JAWS mostly ignore in
  live regions and VoiceOver sometimes reads) and every `alert`
  inserted would be announced on insertion. The oracle asserts the
  `live` property of a mirrored `status` is `off` in
  `Accessibility.getFullAXTree`. touche's mirrored status, log and
  alert are silent to readers in R6; its own HTML `#status` and
  `#network` `role="status"` elements stay on the page, so its
  announcements still reach readers meanwhile (its R6 row says so).
- Landmarks beyond `region`, `heading` levels, `aria-controls` and
  `aria-activedescendant` as element references (A6).
- Native adapters (AccessKit, R7) take the same `AxUpdate`.
- The client-side command API (`window.touche.drive`) is R6b.
