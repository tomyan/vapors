# The accessibility phase, 2026-11-12

R6 PR 4 (`docs/plans/r6.md`, "Where it runs and how it is measured").
The `accessibility` phase of an `ElementsApp` frame takes the a11y
mirror's update (`Document::take_ax_update`) when a mirror is attached
(`ElementsApp::mirror_a11y(true)`). The Rows workload of vapors-perf
attaches one, so `--scaling` judges the phase with the others
(`scaling_judged.rs`): for Idle, Text, Class and HoveredClass it fails,
naming `accessibility`, when the phase grows by more than 2% and 5000
instructions from 1000 to 3000 or 10,000 rows
(`scaling::TOLERANCE_PERCENT`, `MIN_GROWTH_INSTRUCTIONS`); for Insert,
Resize and Scroll, whose cost grows with the rows moved, it fails when
the phase costs more than a ceiling of instructions per extra row
(`INSERT_A11Y_PER_ROW` 9500, `MOVE_A11Y_PER_ROW` 12,500, from the
counts below). The other phases of those three changes are reported,
not judged.

Run: `cargo run --release -p vapors-perf -- 60 10 --scaling <change>`,
once per change. Needs Linux perf events as `mount-2026-11-12.md` says.

## Setup

- Revision: the branch `a11y/r6-phase` (PR 4 of R6) after its review
  fixes (review-v242), on 7e8c320 (main at #236). Release build.
- Hardware: Intel UHD Graphics 630 (Mesa 25.0.7, ANV), headless,
  viewport 640 x 400, scale 1.
- Sizes: 1000, 3000 and 10,000 rows (`scaling::SIZES`); 10 warmup
  frames, 60 kept; median instructions per frame of the calling
  thread's user-space count.
- Load average at the runs: 13 to 15 (other builds on the machine).
  Instruction counts do not follow load; the times in the same runs do
  and are not recorded here.

## The accessibility phase

Median instructions in the `accessibility` span per frame.

| change | 1000 rows | 3000 rows | 10,000 rows | per extra row, 1000 to 10,000 |
|---|---|---|---|---|
| Idle | 1529 | 1529 | 1529 | 0.0 |
| Text | 7635 | 7635 | 7649 | 0.0 |
| Class | 15945 | 16138 | 15909 | 0.0 |
| HoveredClass | 15882 | 16388 | 15945 | 0.0 |
| Insert | 8,850,370 | 25,876,569 | 87,159,764 | 8701 |
| Resize | 11,681,716 | 34,602,444 | 116,984,440 | 11,700 |
| Scroll | 11,698,617 | 34,608,643 | 116,987,091 | 11,699 |

Idle, Insert, Resize and Scroll are from the run after the review
fixes; Text, Class and HoveredClass from the PR's first run (the fixes
touch neither path: no frame of those changes updates twice, and the
take goes through the owner's path with one more comparison).

Idle, with no mirror attached (main before this PR), is 1394: the
empty phase's span. With one attached, an idle frame's take finds
nothing touched and returns, 135 instructions more.

Idle, Text, Class and HoveredClass are judged on every phase
(`Judged::EveryPhase`), and the accessibility phase is flat at every
size: a text change reads the nodes above the text, a class toggle the
nodes whose boxes were built again, whatever the page holds.

Insert, Resize and Scroll are judged on the accessibility phase alone,
against the ceilings above (`Judged::AccessibilityPerRow`): the phase
grows with the page in each, as `r6.md` ("Known non-constant costs")
states. Every row below an insert, a resize or a scroll moves, each
moved box is touched for its bounds, and each touched row's button
record is read and compared. The growth, 8700 to 11,700 instructions
per row, is the per-row cost of the update's `moved` set on this path;
the ceilings hold it there until the splice step bounds what moves
(property 3 of `docs/plans/perf-finish-line.md`), or R6 PR 5's
scroll-relative bounds take a scrolled row out of the touched set.

not judged.

## The other phases

The `update` phase of Class and HoveredClass fails the judge at
10,000 rows on this revision and on main at 7e8c320 alike, through its
`style` step (849,207 instructions at 1000 rows, 870,282 at 10,000:
2.3 per extra row, over 2% and 5000). The numbers are the same with
and without the mirror attached, so the growth is not this PR's; it is
reported to the lead as main's. Idle and Text pass every phase.

## Baselines before this PR

The Rows workload attaches the mirror from this PR on, and native does
not attach one until R7. Every Rows number from this PR on includes
the a11y take in its `accessibility` phase, which the perf records
before it (`baseline-2026-11-10.md` and earlier) do not; with a mirror
attached the `update` phase also collects the boxes each update built,
moved or freed (`touch_slots`), a set insert per box. A comparison of the
`accessibility` phase across this PR compares an empty span (1394)
with a take.

## After PR 5a: bounds from the parent node, scroll containers as nodes

The same runs on `a11y/r6-dom` (#243, PR 5a of R6) after the
scroll-relative bounds: a record's bounds are from its parent node
and a scroll container is a node, so a scroll touches the container
alone and placement's `scrolled` set (the rows moved by the scroll
alone) is left out of the take.

| change | phase | 1000 rows | 3000 rows | 10,000 rows | per extra row, 1000 to 10,000 |
|---|---|---|---|---|---|
| Scroll | accessibility | 6789 | 6789 | 6789 | 0.0 |
| Scroll | update | 26,720,868 | 81,733,739 | 278,239,932 | 27,946 |
| Scroll | draw | 2,888,117 | 2,883,705 | 2,883,581 | -0.5 |
| Insert | accessibility | 9,010,176 | 26,352,878 | 88,739,123 | 8859 |
| Insert | update | 12,039,145 | 35,876,430 | 120,755,359 | 12,080 |
| Resize | accessibility | 12,006,443 | 35,560,576 | 120,195,864 | 12,021 |
| Resize | update | 27,937,489 | 83,242,792 | 281,352,008 | 28,157 |
| Text | accessibility | 7891 | 7877 | 7863 | 0.0 |

Scroll's accessibility phase is flat at 6789 (from 116,987,091 at
10,000 rows): the take reads the body and html above it. Insert and
Resize read each moved row still, now computing its bounds from the
parent as well: 8859 and 12,021 per row (from 8701 and 11,700). The
ceilings: Insert 9500 (unchanged), Resize 13,000
(`RESIZE_A11Y_PER_ROW`), Scroll 1 per row (`SCROLL_A11Y_PER_ROW`:
9000 instructions of growth at 10,000 rows, less than one more node
read). Text's phase is 7891 (from 7635: the body is not a scroll
container on that page, so the difference is the record's relative
bounds and the scroll check per node).
