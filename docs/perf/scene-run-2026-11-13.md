# The racer's 60 s run, 2026-11-13 (P0, today's racer)

One-scene plan row P0 (`docs/plans/one-scene.md`, 3.2 and 3.3) runs
`vapors-perf --scene-run` on today's racer, which draws with its own
`Track` renderer, before any of the one-scene work.

- The run is 3,750 frames: 60 s of the frame clock at 16 ms a frame.
- The scripted driver drives through the racer's own input: keys, and
  clicks on the camera button.
- The livery change scripted at 30 s does nothing on today's racer,
  which has no livery. It is a declared no-op in `racer_driven.rs`
  until R3b adds the livery enum.
- Every frame is judged from the first, with no warmup (D7 (a)).
- A frame is over budget when its time from the start of `App::frame`
  to the return of the GPU wait after it is over 16.7 ms (D6 (a)).

## Setup

- Release build at 4eed56a. Every run prints its revision, and all six
  print `4eed56ac7463`, with no `-dirty` suffix. The binary's sha256 is
  in `scene-run-2026-11-13/sha256.txt`.
- The dev machine: Intel UHD 630 (CML GT2), Mesa 25.0.7 ANV, Vulkan,
  headless, rendering to an offscreen texture with no present. Scale
  1, 1100 x 720.
- The window was quiet: the lead paused every agent's builds. Each run
  checks its 1-minute load average at the start and at the end, and
  refuses 1.5 or more.
- Command: `scripts/scene-runs.sh docs/perf/scene-run-2026-11-13`. It
  runs three pairs. Each pair is a cold run, on a new and empty
  `MESA_SHADER_CACHE_DIR`, then a warm run on the cache the cold run
  filled. Each run's output is kept verbatim in
  `scene-run-2026-11-13/`.
- The tables below are the output of `scripts/scene-run-table.sh`,
  run on those files (cold runs first, then warm runs).
- A run takes about 27 s of wall time. Frames do not wait for a
  display; each starts when the GPU has finished the one before.

## Result

Every run exits 1. In every run exactly one frame is over budget:
frame 0. Under D7 (a), property 9's 60 s run does not hold for today's
racer. The first frame fails whether or not the shader cache is
filled, and it is about four times further over the budget when the
cache is empty.

### Frame 0

Frame 0's extra time is CPU time in the draw phase.

- Cold, about 98 ms to idle: draw takes about 92.6 ms of it, and
  submit about 5.7 ms.
- Warm, about 22 ms to idle: draw takes about 16 ms, and submit about
  5.8 ms.
- The difference between the two, about 76 ms of draw, is compiling
  pipelines that the warm runs found in Mesa's cache.
- The GPU's own time on frame 0 is 4.4 to 4.5 ms in both, the same as
  on later frames.
- Each run's phases for frame 0 are in its output, on the line
  starting `frame 0 at 0.000 s`.

Frame 0 also writes 1,092,268 texture bytes. These include the glyph
atlas's first upload, but the harness reports texture bytes as one
total, so they are not broken down.

A user's first launch has a cold cache. Under D7 (a), the fix is to
move pipeline creation and the other first-use work out of the first
shown frame. The cold figure is the one that fix has to bring under
16.7 ms.

Frames 1 to 3,749 are each 16.7 ms or less in all six runs. Their
largest frame-to-idle time is not recorded: the report keeps only the
first 20 frames one by one. The per-frame work is the same in every
run: 25 draw calls, 33,344 buffer bytes median and 34,304 max, and 0
texture bytes median. `shape_bytes_uploaded` is not reported, because
shapes arrive in S3a1.

## The refusals, each shown failing

The demos below ran at e029341, before the review rounds, in the
window of 01:04 to 01:06. That binary did not print its revision. The
script that ran them and their verbatim outputs are in
`scene-run-2026-11-13/demos-e029341/`.

Each check was broken in a copy of the source, the broken binary was
built and run, and the source was restored. No broken copy was
committed.

- **A frame made slow.** A 20 ms sleep inside frame 100's timed window
  makes the run exit 1, naming `frame 100 at 1.600 s: to idle
  22773.6 µs` beside frame 0 (`demo-slow.txt`).
- **A GPU reading withheld.** Frame 200's reading was replaced with
  `GpuTime::Pending`. The run ends there with exit 1:
  `frame 200: no GPU time was read back` (`demo-withheld.txt`).
- **Load faked high.** `/proc/loadavg` was replaced with
  `2.00 1.00 1.00`. The run is refused before the first frame with
  exit 1 (`demo-load-high.txt`).
- **A device without timestamp queries.** Not run: every device on the
  dev machine has timestamp queries. The unit test
  `a_device_without_timestamp_queries_is_refused_naming_it` covers it.
- **Mesa's default shader cache.** Added after e029341. With neither
  `MESA_SHADER_CACHE_DIR` nor `MESA_SHADER_CACHE_DISABLE` set, the run
  is refused before the GPU is opened. Its unit tests cover the
  refusal, and the 4eed56a binary was also seen refusing.
