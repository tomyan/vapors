# The racer's 60 s run, 2026-11-13 (P0, today's racer)

One-scene plan row P0 (`docs/plans/one-scene.md`, 3.2 and 3.3):
`vapors-perf --scene-run` on today's racer (its own `Track` renderer,
before the one-scene work). The run is 3,750 frames, which is 60 s of
the frame clock at 16 ms a frame. The scripted driver drives through
the racer's own input. Every frame is judged from the first, with no
warmup (D7 (a)). A frame is over budget when its time from the start
of `App::frame` to the return of the GPU wait after it is over
16.7 ms (D6 (a)).

## Setup

- Release build, at e029341 (branch `perf/p0-scene-60s` before the
  review rounds of #259 and #261), built as
  `cargo build --release -p vapors-perf`.
- The dev machine: Intel UHD 630 (CML GT2), Mesa 25.0.7 ANV, Vulkan,
  headless, rendering to an offscreen texture with no present. Scale
  1, 1100 x 720.
- The window was quiet: the lead paused every agent's builds. Each run
  printed its 1-minute load average at the start and at the end, and
  all six readings were under 1.5.
- A run takes about 27 s of wall time. Frames do not wait for a
  display; each starts when the GPU has finished the one before.
- Command: `vapors-perf --scene-run`. To reproduce:
  `cargo run --release -p vapors-perf -- --scene-run`.

```
run1 start 01:04:22 load 0.76 0.99 5.08
run1 end 01:04:49 exit 1 load 0.73 0.96 4.94
run2 start 01:04:49 load 0.73 0.96 4.94
run2 end 01:05:15 exit 1 load 0.82 0.96 4.83
run3 start 01:05:15 load 0.82 0.96 4.83
run3 end 01:05:42 exit 1 load 0.80 0.95 4.72
```

The review rounds of #259 and #261 changed only the driver's checks
and its camera input. Each frame now also checks that the racer is not
paused and holds the keys the script sent. The camera is set to a
named mode, so it is clicked only when it is in the other mode. The
schedule names Follow at 10, 30 and 50 s and Fixed at 20 and 40 s,
which is the same sequence the toggles gave in these runs. These runs
were not repeated after those changes.

## The refusals, each shown failing

Each check was broken in a copy of the source at e029341. The broken
binary was built and run, and the source was then restored. No broken
copy was committed.

- **A frame made slow.** A 20 ms sleep was added inside frame 100's
  timed window (`Sampler::timed`). The run, in the same quiet window,
  exits 1 and names that frame beside frame 0:
  `frame 100 at 1.600 s: to idle 22773.6 µs, CPU 22476.2 µs, GPU
  5017.2 µs; phases (µs) ... draw 1752.4 ...`.
- **A GPU reading withheld.** Frame 200's reading was replaced with
  `GpuTime::Pending`. The run ends there with exit 1:
  `FAIL perf: frame 200: no GPU time was read back`.
- **Load faked high.** `/proc/loadavg` was replaced with
  `2.00 1.00 1.00`. The run is refused before the first frame with
  exit 1: `FAIL perf: the 1-minute load average is 2.00 at the start;
  the run needs under 1.5: wait until uptime shows it, then cargo run
  --release -p vapors-perf -- --scene-run`. The real load does the
  same: at 14.28, before the window, the unbroken binary was refused
  with the same message.
- **A device without timestamp queries.** This was not run, because
  the dev machine's devices all have timestamp queries. The unit test
  `a_device_without_timestamp_queries_is_refused_naming_it` covers it,
  and was proven by making the check always pass, which failed the
  test.
