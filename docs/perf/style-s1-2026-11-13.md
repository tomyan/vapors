# Style S1: cascade values copied once (2026-11-13, main at 00dbc38b)

Slice S1 of `docs/plans/style-allocations.md`: a winner refers to its
declaration's value (`Winners<'a>`, `collect.rs`), and each longhand's
computed value is built from one `Source` (`compute.rs`): a declared
value resolved, the initial value resolved, a `var()` winner substituted
then resolved, or the parent's computed value copied as it is
(`compute_source.rs`). Matching
allocates nothing per class test (`has_class` scans the attribute,
`css_element.rs`) and the candidate list is one allocation
(`buckets.rs`). Before, every longhand's value was cloned into a
`specified` vec and cloned once more by `resolve`, whether or not the
element declared it: about 720 of an unkeyed element's 900 heap calls
per restyle (the plan's section 2).

## Why

The per-element profile of the rows Insert frame (2026-11-13, perf
sampling over the same `Cascade::compute` the mount runs) put the
cascade at about 104k instructions per restyled element, of which
`compute_resolve::resolve` was 32% (`other.clone()` of every non-length
value), `specified_value` 25% (a clone of the winner's, parent's or
initial value per longhand) and the allocator's own work, by leaf, 53%;
matching was about 3k. The `Used` derivation was about 15k per element.

## Measured

`vapors-perf 60 10`, release, Intel UHD 630, load 30 to 50 (instruction
counts do not move with load). "Before" is main at 00dbc38b with #279
(the insert's tree check made flat in rows, so the Insert frames can be
compared per element); "after" is this branch on main without #279, so
its Insert frames still carry the body check's 45 instructions per row,
which the per-element reading below subtracts.

Per restyled element on an insert at 1000 rows (insert frame minus the
remove frame, which has the same checks and no restyle, less the
per-insert work around the restyle measured on 2026-11-13: `touched`
29k, `dirty_roots` 23k, the checks 28k): before (548,998 − 8,180 −
80k) / 4 ≈ 115k; after (445,933 − 59,688 − 80k) / 4 ≈ 77k, of which
the `Used` derivation is about 15k. The cascade went from about 100k
to about 61k per element (−40%); a Class edit's style phase, four
elements restyled, from 600k to 403k.

`--scaling Class` still fails on main and here on `paint` (13.6
instructions per extra row on the add frames, `docs/plans/
perf-finish-line.md`; #288's), and `--scaling Insert` on the
accessibility ceiling as on main; `style` passes on both.

## Checks

- `crates/css/tests/cascade_compute_sources.rs`: one test per source: a
  declared `em` resolved against the element's own font size; an
  inherited `line-height: 150%` copied from the parent as its computed
  px (15px, not 150% of the child's font size); `inherit` on a
  non-inherited property copying the parent's computed `em` border;
  `unset` on an inherited and a non-inherited property; `initial`; a
  `var()` winner substituted then resolved; a `var()` substituting to
  `inherit`. All seven pass before and after the change (the paths
  compute the same values; the tests pin that).
- The copy oracle: `copied` (`compute_source.rs`) asserts in debug builds
  that the parent's computed value resolves to itself in the child's
  context, naming the property. Proven by breaking: with a declared
  value stored unresolved (`Source::Declared` returning the value as
  is), the inherited line-height test fails at the assertion:
  "line-height: the parent's computed value `150%` does not resolve to
  itself". Restored.
- The css crate's tests and every elements test
  (`incremental_styles`, `incremental_inherit`, `incremental_random`,
  `sparse_updates` among them) pass with the oracle on.
