# The racer's 60 s run on SceneRenderer, 2026-11-17 (R3a2; F8's "before")

One-scene R3a2 moved the racer onto `SceneRenderer` (the Track renderer
deleted). This is P0's run on it, as `docs/perf/scene-run-f0-2026-11-14.md`
ran it on the Track: 3,750 frames of the racer's scripted drive, every
frame judged from the first, a frame over budget when its time from the
start of `App::frame` to the return of the GPU wait after it is over
16.7 ms. It is F8's "before" (R3a2 Q5, L58 Q8), at 1 and 4 samples.

## Setup

- Release build at b1af2a0a (R3a2's branch: 9b2b2710's code and
  `scripts/scene-runs.sh` taking a sample count). Every run prints
  `b1af2a0af79d`; the binaries' sha256 are in `samples-*/sha256.txt`.
- The dev machine: Intel UHD 630 (CML GT2), Mesa 25.0.7 ANV, Vulkan,
  headless; the script's defaults, an offscreen texture with no present,
  scale 1, 1100 x 720.
- `cargo xtask quiet 60 -- <loop>`, the loop running
  `scripts/scene-runs.sh <dir> racer <samples>` for 1 then 4, each set
  retried into a fresh directory when a run was refused: the script
  settles the load once, and other agents' builds raised it mid-set.
  The refused attempts' logs are in `retry.txt`; the kept sets had a
  1-minute load of 0.53 to 1.39 at each run's start and end.
- Three pairs a count, each a cold run on a new, empty
  `MESA_SHADER_CACHE_DIR` and a warm run on the cache it filled. The
  tables are `scripts/scene-run-table.sh` on the kept outputs.

## Result

At 1 sample every run exits 0: no frame over budget. At 4 samples one
run, run3-cold, has one frame over budget: its frame 0, 18.7 ms to idle
(14.4 ms of it CPU, on a cold shader cache). The other two cold runs'
frame 0 took 15.1 and 14.7 ms; the warm runs', 10.4 to 10.6 ms. F0's
acceptance (frame 0 under 16.7 ms, cold and warm) held on the Track,
where frame 0 took 6.2 to 6.5 ms cold; on SceneRenderer at 4 samples it
does not hold in one cold run of three. At 1 sample frame 0 took 8.2 to
12.2 ms.

Over the runs (median of the runs' medians):

| time | Track, F0 (2026-11-14, 1 sample) | SceneRenderer, 1 sample | SceneRenderer, 4 samples |
|---|---|---|---|
| frame (CPU) µs | 2121.5 | 2397.3 | 2906.5 |
| GPU time µs | 5118.9 | 5301.0 | 6991.8 |
| frame to idle µs | 7088.0 | 7521.0 | 9553.2 |

## After frame 0's fix (d3974489, L72)

The runs above put one cold frame 0 at 4 samples over budget: its draw
phase was 13.9 ms of CPU, the world's first render (592 KB of geometry
and uniforms, the pipelines' first draws). d3974489 renders each
surface once at `App::start`, as F0 moved the painter's first-frame
work there. The same runs again, at d3974489 (retries in
`after-frame-0/retry.txt`): no frame over budget at either count.

| frame 0 to idle | cold runs | warm runs |
|---|---|---|
| Track, F0 (1 sample) | 6.2 to 6.5 ms | |
| SceneRenderer, 1 sample, before | 8.3 to 8.5 ms | 8.2 to 12.2 ms |
| SceneRenderer, 1 sample, after | 6.1 to 6.2 ms | 6.1 to 9.3 ms |
| SceneRenderer, 4 samples, before | 14.7 to 18.7 ms | 10.4 to 10.6 ms |
| SceneRenderer, 4 samples, after | 8.1 to 8.2 ms | 8.1 to 10.6 ms |

At 1 sample frame 0 is back at the Track's. At 4 samples what remains is
the 4x frame itself: frame 0's GPU time is 6.0 to 6.1 ms, as every
frame's is at 4 samples (6.99 ms median), against 4.5 to 4.6 ms at 1;
its CPU is 3.2 to 3.4 ms. In both counts one warm run (run2-warm both
times) took 7.6 to 7.7 ms of CPU in frame 0, twice the others; that is
not explained here.
