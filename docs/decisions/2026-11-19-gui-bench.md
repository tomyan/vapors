# Adopt gui-bench as vapors' comparative benchmark

Date: 2026-11-19. Decided by: Tom, with the lead. Supersedes
`docs/plans/comparative-benchmark.md`, which stays for its research on
fairness and per-framework driving.

## Decision

1. **vapors is measured with [gui-bench](https://github.com/zortax/gui-bench)**
   in place of the harness `comparative-benchmark.md` planned. gui-bench
   runs each framework's app under fakeland, a headless Wayland
   compositor that sends real input and times every frame: an analytics
   dashboard at 30 to 3,000 rows (558 to 33,228 elements), a virtual list
   at 10,000 and 1,000,000 rows, response times for hover, click, key and
   page switches, and scroll and animation pacing at 144 Hz. It already
   covers zgui, GPUI, freya, vizia, floem, iced, egui, Dioxus Native and
   Tauri, and its rules for idiomatic apps (`IDIOMS.md`) match the
   fairness rules the old plan set out to write.
2. **The app lives in this repository** as `crates/gui-bench-app`
   (binary `vapors-bench`, `--scenario app|list --rows N`), built from
   the vendored spec in `docs/gui-bench/spec/`. vapors CI keeps it
   building as the framework changes, and API harness builders can work
   on it offline. A gui-bench checkout gets `apps/vapors` as a thin
   crate depending on vapors at a commit, plus its runner entry.
3. **Measurement runs on the host**, from a script: fakeland needs a
   compositor and a GPU, which the builder sandbox does not have.
   Baselines: zgui, egui and iced first.
4. **Results are published only once vapors is competitive** (Tom). The
   app's code is public in this repository from its first slice; the
   numbers stay local until then.
5. **Parts vapors lacks are built in the app by hand and flagged**, as
   `IDIOMS.md` rule 5 requires (virtual list, menu, switch, text input
   in a table are expected). Each flagged part, and each step where
   vapors loses to zgui, becomes a framework slice, ordered by loss.
   Expected candidates: damage tracking and damage-bounded paint,
   incremental layout, O(changed) insert and remove, scroll compositing,
   startup.

## Slices

- s0: vendor the spec, this record (this pull request).
- s1 to s3: `crates/gui-bench-app` in three builder slices: window,
  sidebar, top bar and metric cards; chart, filters and orders table;
  messages page, export menu, live switch and the `list` scenario.
- s4: the host script: build fakeland, the runner, the baselines and
  `apps/vapors`; run the matrix; write a ranked gap list.
- Then framework slices from the gap list.
