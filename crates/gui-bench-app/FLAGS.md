# Parts built by hand (`IDIOMS.md` rule 5)

Part, what vapors lacks, the smallest framework change. The window, the sidebar and the metric cards, the page switch and the messages feed are plain elements and CSS. The `list` scenario uses vapors' own virtual list, `vapors_components::virtual_list::VirtualList` (`docs/virtual-list.md`), added to the framework for this scenario rather than built in the app; it fills the window below the header and its rows follow its laid-out height as the window resizes (`src/tests/list_resize.rs`).

| Part | What vapors lacks | The smallest change |
|---|---|---|
| search input placeholder | Eliminated: the input's own `placeholder`, in the spec's `MUTED` by `::placeholder { color }` (`docs/placeholder.md`); `src/tests/search_hint.rs`. | None. |
| search input look | The user-agent sheet gives an input `display: inline-block`, laid out only as a flex item, so the input sits in a flex box. Its text scrolls inside its content box, as Chromium's does (the user-agent sheet's text field rule, entry 44), cut off clear of its rounded corners by its 12 px side padding; `src/tests/long_search.rs` holds a 60 character search's caret in the content box's last column. | Lay an inline-block input out outside flex and grid (`docs/F2c.md`). |
| compare switch | A checkbox with `appearance: none` (`docs/appearance.md`): `<input type=checkbox switch bind:checked>`, whose background (the spec's `SWITCH_OFF`, `PRIMARY` when `:checked`) and 11 px radius are the track, followed by a decorative `aria-hidden` sibling as the knob, an 18 px white circle 2 px inside with the spec's `SHADOW_SMALL` as `box-shadow`, moved to the end by `:checked + .knob`, with `pointer-events: none` so a press on it reaches the checkbox. Sized 40 by 22 px with `display: block` as before. `src/tests/switch_knob.rs` holds one knob and its shadow in each state, and a press on the knob toggling and focusing the switch. | – |
| chart bar heights | Eliminated: each bar binds `style:height` of the spec's `bar_height` / `previous_height` at the series and slot (`src/chart_bars.rs`), in place of 72 per-series rules; `tests/chart_heights.rs` holds the app to a live Chromium oracle (`tests/chart_oracle.rs`, needs Chromium, no stored boxes) for all 3 series, compare off and on, before and after each update. | None. |
| status checkbox look | The user-agent sheet gives an `input` `display: inline-block`, laid out only as a flex item, so each checkbox sits in a flex row (as the search input does). | Lay an inline-block input out outside flex and grid (`docs/F2c.md`). |
| export menu | vapors has no menu or popover (`docs/F2c.md` defers `dialog`/popover), so the menu has no light dismiss, focus handling or top layer. `ExportMenu` is a `div` of items, open by a signal that the button toggles, placed with plain CSS and no coordinates copied from the spec: the button and the menu share a positioned box in the top bar (`.export-anchor`, which keeps the spec's 84 px from the right edge, as the other top bar controls keep theirs), and the menu sits at `left: 0; top: 40px` in it with `z-index: 1`, over the content's positioned cards. `src/tests/menu_anchor.rs` holds, at 1280 and 1000 px, the boxes of the five controls, the menu's box under the button, and, at a point over the fourth metric card, the menu's box as the last quad painted and its item as the hit. The title keeps its left edge, so in a window narrower than 958 px the search input (its left edge 604 px from the right edge) paints over the title (which ends at x 354), and below 844 px the search input reaches the sidebar; Zgui's flex top bar shrinks and clips the title instead. | A popover part (light dismiss, focus, the top layer); the placement needs no framework change. |
| message avatar colours | Eliminated: the avatar binds `style:background-color` of the palette entry (`src/data_colours.rs`, which refuses an index past the 8); the 8 classes are gone. | None. |
| order progress fill | Resolved: `style:width={..}` (#585) binds one fill's width to the percentage, `progress * 1.2` px of the 120 px track; the 7 bit segments are gone. `order_parts.rs` still refuses a percentage above 100 (`u32`, so never negative); `tests/progress_fill.rs` holds all 101 widths, both endpoints and the widths after a sort, and the corpus fixture `progress_fill` holds the same widths to Chromium's boxes. | none |
| order status pill and avatar colours | Eliminated: the avatar binds `style:background-color`, the pill `style:background-color` and `style:color` (`src/data_colours.rs`: 8 palette entries, 4 statuses, an index past them refused); `tests/data_colours.rs` holds every entry, foreground and background, and `tests/data_colours_oracle.rs` holds 30 rows to a live Chromium (`cargo test -p vapors-gui-bench-app data_colours_oracle`, exact colours, no stored values) and fails under a deliberate mismatch. The `pill` and `order-avatar` classes stay for the layout. | None. |
| orders card corners | A rounded clip is deferred (as for the search input), so the card does not clip its rows: the header rounds its own top corners, and the last row, on hover, has square bottom corners over the card's round ones. | Honour a rounded clip (`overflow: hidden` with a radius). |
| live switch | Drawn as the compare switch: `<input class=live-switch type=checkbox switch bind:checked={live.on} aria-label>` with `appearance: none`, then its knob `<div class=live-knob aria-hidden=true>`; `tests/live_switch.rs` holds its pointer, Space, name, role, checked state and painted track and knob, `tests/switch_knob.rs` its knob's shadow, and the corpus fixture `live_switch` holds its box, click, Space, Enter, Tab, name and checked state to Chromium (`cargo run -p vapors-elements-corpus --example events_oracle -- --check`, `cargo test -p vapors-elements-corpus --test events_every_script`). The tick is not a timer part either: vapors has `frame_time()`, the frame clock, which the loop follows while a reader lives, so `src/live.rs` counts `LIVE_INTERVAL_MS` of it, from the second frame after the click (the first read is the last frame's, older by the idle wait). | An interval timer (`set_interval`-like, waking the loop only while it runs). |
| spinner | `transform` and `@keyframes` animations are deferred (`docs/F2c.md`), and an svg shape takes no `transform`. The spinner is an svg `path` whose `d` is computed each frame from the clock (the square's four rounded corners, turned in `live.rs`), in an svg 34 px wide with a negative margin, since a filled svg shape is not clipped and may not leave its viewBox. | `transform: rotate()` with an `animation` honoured in `crates/elements`. |

Compiler gaps met on the way, both closed: a generated `mount_before` no longer trips `clippy::needless_pass_by_value` for `Copy` props that are not signals (it moves its props whole, so the crate-wide allowance is gone), and a `#[prop]` may be declared without a default (`#[prop] let controls: Controls;`), which the compiler checks at each tag in the crate and the mount refuses at run time (`docs/components.md`, "Required props").
