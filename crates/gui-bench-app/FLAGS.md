# Parts built by hand (`IDIOMS.md` rule 5)

Part, what vapors lacks, the smallest framework change. The window, the sidebar and the metric cards, the page switch and the messages feed are plain elements and CSS.

| Part | What vapors lacks | The smallest change |
|---|---|---|
| search input placeholder | `<input placeholder>` is not painted or read: the compiler and the style engine have no placeholder. The top bar puts a `div` over the input, shown while the bound signal is empty, and `pointer-events: none`. | Paint `placeholder` of an empty text input (`::placeholder` colour) in `crates/elements`. |
| search input look | The user-agent sheet gives an input `overflow: hidden`, which vapors refuses with a border radius, and `display: inline-block`, laid out only as a flex item. The input sits in a flex box and sets `overflow: visible`, so a long text is not clipped to its rounded box. | Honour a rounded clip on an input (`docs/F2c.md` defers rounded clips). |
| scroll container axes | `overflow-y: auto` alone is refused (axes that differ). The content sets `overflow: auto` on both axes; it scrolls vertically only because nothing is wider. | Honour a one-axis scroll container. |
| sparkline bar heights | No `style=` and no `class={..}` with a computed name: the compiler must see every class. The 12 heights of the spec (even, 14 to 44) are 16 classes of the card, each toggled with `class:hN`. | A per-element `style:height={..}` directive that the style key admits. |
| compare switch | vapors has no switch: `<input type=checkbox>` is the one toggle part, and its box and mark are not a track and a knob. The filter card builds it from a `div` track, a `div` knob and an `onclick`, with the `on` class for the state. | A `switch` part (a checkbox restyled as a track and knob, role `switch`) in `crates/elements`. |
| chart bar heights | Same gap as the sparkline: no computed style. The 72 bars of the three series, and their previous-period bars, are 72 rules `.sN .slot:nth-child(i) .cur` / `.prev` with the spec's heights written out (the layout test holds each to `bar_height` and `previous_height`); the series and compare state are classes of the plot. | A per-element `style:height={..}` directive that the style key admits. |
| status checkbox look | The user-agent sheet gives an `input` `display: inline-block`, laid out only as a flex item, so each checkbox sits in a flex row (as the search input does). | Lay an inline-block input out outside flex and grid (`docs/F2c.md`). |
| export menu | vapors has no menu or popover (`docs/F2c.md` defers `dialog`/popover). `ExportMenu` is an absolutely placed `div` of items, after the content so it paints over it, open by a signal that the button toggles; no light dismiss. Its `left`/`top` are hand-written CSS copies of `MENU_X`/`MENU_Y`, held by a test. | A popover part anchored to its button with a layer above the content. |
| message avatar colours | No computed style (as the sparkline). The 8 avatar colours are 8 classes, toggled by the author's colour index; a test holds each class's colour to `AVATAR_COLORS` and its length to 8, and an unknown colour panics. | `style:background-color={..}`. |
| order progress fill | No computed style (as the sparkline), and the fill is 0 to 100 % of 120 px: 101 widths. The fill is a flex row of 7 empty segments, one per bit of the percentage (1.2 px, 2.4 px .. 76.8 px), each widened by a `class:on`; the row refuses a percentage above 100, and a test holds all 101 widths (and that the data has all 101) to the spec's. | `style:width={..}`. |
| order status pill and avatar colours | No computed style. The 4 status pills are 4 classes and the 8 avatars 8 classes, toggled by index; the row refuses an index out of range, and a test holds each pill and avatar to `Status::colors` and the order's avatar colour. | `style:background-color={..}`. |
| orders card corners | A rounded clip is deferred (as for the search input), so the card does not clip its rows: the header rounds its own top corners, and the last row, on hover, has square bottom corners over the card's round ones. | Honour a rounded clip (`overflow: hidden` with a radius). |

Not a missing part, a compiler gap met on the way: the compiler allows `clippy::needless_pass_by_value` on a generated `mount_before` only when every prop is a signal or memo, so a component whose props are `Copy` but not signals (`Controls`, `usize`) trips it. `main.rs` allows it crate-wide, with the reason. The smallest change: derive the allowance from the props' types, or take `props` by reference. Also: a `#[prop]` always has a default, so `Controls::unbound()` is the default and `Controls::bound(who)` refuses it loudly; the smallest change is a required `#[prop]`.
