# Parts built by hand (`IDIOMS.md` rule 5)

Part, what vapors lacks, the smallest framework change. The window, the sidebar and the metric cards, the page switch and the messages feed are plain elements and CSS.

| Part | What vapors lacks | The smallest change |
|---|---|---|
| search input placeholder | `<input placeholder>` is not painted or read: the compiler and the style engine have no placeholder. The top bar puts a `div` over the input, shown while the bound signal is empty, and `pointer-events: none`. | Paint `placeholder` of an empty text input (`::placeholder` colour) in `crates/elements`. |
| search input look | The user-agent sheet gives an input `overflow: hidden`, which vapors refuses with a border radius, and `display: inline-block`, laid out only as a flex item. The input sits in a flex box and sets `overflow: visible`, so a long text is not clipped to its rounded box. | Honour a rounded clip on an input (`docs/F2c.md` defers rounded clips). |
| compare switch | Now the `switch` part (`docs/switch.md`): `<input type=checkbox switch bind:checked>` with `accent-color` and `--vapors-track-color` for the spec's colours, sized 40 by 22 px as before, with `display: block` (the user-agent inline-block is laid out only as a flex item, as for the status checkbox). Not met: the knob's drop shadow, which the part does not draw. | A knob shadow on the `switch` part (a `box-shadow` on a part, or `::part(knob)`). |
| chart bar heights | Eliminated: each bar binds `style:height` of the spec's `bar_height` / `previous_height` at the series and slot (`src/chart_bars.rs`), in place of 72 per-series rules; the corpus fixture `chart_heights` holds Chromium's boxes for all 3 series, compare off and on, and `tests/chart_heights.rs` holds the app to them before and after each update. | None. |
| status checkbox look | The user-agent sheet gives an `input` `display: inline-block`, laid out only as a flex item, so each checkbox sits in a flex row (as the search input does). | Lay an inline-block input out outside flex and grid (`docs/F2c.md`). |
| export menu | vapors has no menu or popover (`docs/F2c.md` defers `dialog`/popover). `ExportMenu` is an absolutely placed `div` of items, after the content so it paints over it, open by a signal that the button toggles; no light dismiss. Its `left`/`top` are hand-written CSS copies of `MENU_X`/`MENU_Y`, held by a test. | A popover part anchored to its button with a layer above the content. |
| message avatar colours | No computed style (as the sparkline). The 8 avatar colours are 8 classes, toggled by the author's colour index; a test holds each class's colour to `AVATAR_COLORS` and its length to 8, and an unknown colour panics. | `style:background-color={..}`. |
| order progress fill | Resolved: `style:width={..}` (#585) binds one fill's width to the percentage, `progress * 1.2` px of the 120 px track; the 7 bit segments are gone. `order_parts.rs` still refuses a percentage above 100 (`u32`, so never negative); `tests/progress_fill.rs` holds all 101 widths, both endpoints and the widths after a sort, and the corpus fixture `progress_fill` holds the same widths to Chromium's boxes. | none |
| order status pill and avatar colours | No computed style. The 4 status pills are 4 classes and the 8 avatars 8 classes, toggled by index; the row refuses an index out of range (`order_parts.rs`, held by `should_panic` tests; `PILLS` is tied to `Status::ALL` at compile time), and a test holds each pill and avatar to `Status::colors` and the order's avatar colour. | `style:background-color={..}`. |
| orders card corners | A rounded clip is deferred (as for the search input), so the card does not clip its rows: the header rounds its own top corners, and the last row, on hover, has square bottom corners over the card's round ones. | Honour a rounded clip (`overflow: hidden` with a radius). |
| live switch | As the compare switch (no `switch` part); the top bar's is the same `div` track, `div` knob and `onclick`, with the `on` class. The tick is not a timer part either: vapors has `frame_time()`, the frame clock, which the loop follows while a reader lives, so `src/live.rs` counts `LIVE_INTERVAL_MS` of it, from the second frame after the click (the first read is the last frame's, older by the idle wait). | A `switch` part, and an interval timer (`set_interval`-like, waking the loop only while it runs). |
| spinner | `transform` and `@keyframes` animations are deferred (`docs/F2c.md`), and an svg shape takes no `transform`. The spinner is an svg `path` whose `d` is computed each frame from the clock (the square's four rounded corners, turned in `live.rs`), in an svg 34 px wide with a negative margin, since a filled svg shape is not clipped and may not leave its viewBox. | `transform: rotate()` with an `animation` honoured in `crates/elements`. |

Compiler gaps met on the way, both closed: a generated `mount_before` no longer trips `clippy::needless_pass_by_value` for `Copy` props that are not signals (it moves its props whole, so the crate-wide allowance is gone), and a `#[prop]` may be declared without a default (`#[prop] let controls: Controls;`), which the compiler checks at each tag in the crate and the mount refuses at run time (`docs/components.md`, "Required props").
